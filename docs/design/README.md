# DOT MIC v3.2 — 完成度を維持する実装・最小検証パック

改訂日：2026-10-06。v3.2はモデル別のエージェント運用ルールとE4→E5のRC freezeを反映した版。対象は設計と実装指示であり、アプリ本体を実装・実機検証した成果物ではない。

## 今回の方針
機能を後回しにするMVPではなく、指定した音声・UI・常駐機能を今回の納品で完成させる。削るのは、重複文書、工程ごとの承認、網羅的な証明、理由のない反復、必要性のない汎用基盤である。未完成機能を「次の更新で対応」として完成扱いにしない。

v1/v2の設計パックを本パックで置き換える。旧56項目の一律必須ゲート、P0〜P7、100回トグル、30分実時間試験、全条件3回のベンチ、動画必須、文書検証器の実行義務は継承しない。動いている既存実装や役立つテストは消さず、差分だけを直す。

## 開始
このフォルダーの中身を実装先の `docs/design/` に配置し、`START_PROMPT.txt` を主実装セッションへ渡す。既存AGENTSや利用者作成ファイルを上書きしない。通常工程では確認待ちにせず、`IMPLEMENT.md` のE1→E5へ続ける。

|資料|用途|
|---|---|
|IMPLEMENT.md|開始・全工程・最終セルフレビュー・中断再開を一つにした主プロンプト|
|PRODUCT_AND_MOTION.md|製品、二つの画面、操作、アニメーション、Windows統合|
|AUDIO_AND_NC.md|音声実装、DPDFNet契約、独立dry、クロック、終了|
|OPTIMIZATION_AND_TESTS.md|専用最適化フェーズと、最低限の自動／実機確認|
|defaults.json|共通の数値・固定選定。試験IDや工程管理は含めない|
|REVIEW.md|v2から何を削り、何を残したか。新規／実装済みの扱い|
|SOURCES.md|先例とAPIの参照先。必要な箇所だけ読む|

最初から全資料を何度も読む必要はない。IMPLEMENTとdefaultsを先に読み、該当工程の仕様を必要時に開く。統合版Markdownは閲覧用であり、分割版と両方を実装担当へ読ませない。


## エージェント運用
このルールはDOT MIC固有ではなく、利用者の全プロジェクト共通方針として扱う。**実行モデルがAstraの場合に限り**、主エージェント単独で処理し、サブエージェント・並列エージェント・別レビューエージェントを使用しない。**Astra以外のモデルでは、これらのエージェント数・並列化制限は無効**であり、速度または品質に実益がある場合はサブエージェント、並列エージェント、独立レビューを利用してよい。

モデルを問わず、同一作業ツリーの競合編集、重複作業、エージェント数を増やすこと自体を目的にした分業は避ける。これはエージェント利用制限ではなくリポジトリ整合性と実装効率のための運用原則である。Astra以外で複数担当を使う場合も統合責任を一つに保つ。

## 最低限の検証
実行入口は「コア自動試験1本」と「配布版の実機確認1セッション」にまとめる。後者に最適化の基準測定、音声、UI、常駐の確認を兼用する。変更した場合にだけ影響箇所を再確認する。個別条件と失敗時の扱いはOPTIMIZATION_AND_TESTSに定める。

短時間の検証は、多機種・長時間・低頻度障害を網羅した証明ではない。その範囲を明記しつつ、要求機能が完成して動作する成果物を渡す。未実行をPASSにはしないが、動画がない、実ゲームが手元にない等を理由に関係のない完成済み部分まで一括未完成にしない。

## Release candidateの固定
E4最適化の最後に最終Release candidateをfreezeし、その同一バイナリをE5で原則再ビルドせずpackageする。性能を測ったバイナリと配布したバイナリの不一致を避ける。clean buildは必要な場合の再現性確認に限定し、配布物を差し替える場合だけ影響範囲を再確認する。
